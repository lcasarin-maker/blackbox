# Hardware batch 03 verifier contract

`tools.hardware_batch03_controls.verify(card_id, evidence_path)` is an experimental, read-only evaluator for the seven exact generated IDs. It reads `capture.json` and bounded UTF-8 artifacts (8 MiB per input), requires schema 1 and exact card identity, exact `tools.host_diagnostics` and `tools.thermal_coverage` collector argv, shell-free literal command receipts, unique capture names, non-symlink paths contained under the dossier, successful process return codes, and independently recomputed SHA-256 output matching each raw artifact. It cross-checks the running kernel/architecture between the collectors, reads DMI identity, and parses the study JSONL into per-card predicates. The OEM thermal-limit document uses a strict four-key `key=value` contract and rejects malformed, duplicate, unknown, or missing rows. Rollback comparison requires matching nonempty SHA-256 maps.

The supplied command/capture metadata remains caller supplied. Matching digests establish byte consistency only; they do not authenticate the operator, device, command execution, or OEM source. For thermal-coverage, the verifier parses the preserved collector JSON itself, validates its UTC timestamp, scan counts/statuses, sensor channel records and parsed numeric values, recomputes `could_not_run`, then requires the soak and every per-source row to bind the collector's exact SHA-256 and timestamp. A collector with unresolved read/scan failures yields `unknown`/CNR even when the caller's study rows otherwise look complete. Optional missing-channel declarations stay separate from collector failures. Study time-series freshness, firmware signature receipt, journal records and power-loss capture remain caller-supplied JSONL rather than linked raw command artifacts. See each row of `matrix.json` for exactly which criteria are recomputed and which capture bindings remain open. Consequently none of the synthetic unit positives close a real investigation.

A complete unit fixture validates evaluator behavior only. Missing, unreadable, malformed or insufficient subject evidence returns `unknown` with `could_not_run_count > 0`; contradictory observed data returns `fail`. CLI exit codes are 0/1/2 for pass/fail/unknown. Current real dossier checks are unknown: six card evidence directories are absent, and the existing thermal-coverage prototype lacks the required schema/card binding. No thermal intervention, power-loss test, storage write, display carveout change, firmware update, hotplug, cooling canary, reboot or GPU workload was run.
