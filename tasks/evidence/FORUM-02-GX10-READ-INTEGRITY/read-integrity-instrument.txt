FORUM-02-GX10-READ-INTEGRITY — instrument evidence

`tools/read_integrity.py` opens the selected regular file twice: once buffered and once
with `O_DIRECT`. It checks both descriptors against the non-following path identity
before reading, then checks descriptor and path identities again after reading. A path
replacement between opens yields `could_not_run`. If opening `O_DIRECT` fails, the
buffered descriptor is closed before returning. Every result includes
`could_not_run_count` (zero for pass/fail and one for an unavailable check).

Each invocation reads one caller-selected region no larger than 1,048,576 bytes. Offset,
length, memory, and direct-I/O requests use 4,096-byte alignment. SHA-256 digests from
both modes are compared with the supplied reference; output labels it
`caller-supplied; provenance unverified`. Reads are read-only. No cache drop, global cache
control, telemetry or firmware collection is performed.

Positive and negative controls used a disposable 4,096-byte file containing `a` repeated
4,096 times. Python generated the reference from this fixture; it is a plumbing control,
not an independent trust anchor. Literal command:

```sh
python3 - <<'PY'
import hashlib, subprocess, sys, tempfile
from pathlib import Path
with tempfile.TemporaryDirectory(prefix='bb-read-integrity-') as directory:
    path = Path(directory) / 'region.bin'
    region = b'a' * 4096
    path.write_bytes(region)
    digest = hashlib.sha256(region).hexdigest()
    for label, reference in [('healthy-control', digest), ('corrupted-reference-control', '0' * 64)]:
        result = subprocess.run([sys.executable, '-m', 'tools.read_integrity', str(path), '--offset', '0', '--length', '4096', '--sha256', reference, '--repeats', '1'], text=True, capture_output=True, check=False)
        print(label, 'exit=', result.returncode)
        print(result.stdout.strip())
PY
```

Limits: the reference's provenance is unverified, the digest does not identify the
changed byte, and only the selected region is read. This instrument does not measure
NVMe health, RAS/EDAC/BERT signals, firmware, or a full model. No result attributes a
problem to cache, RAM, storage, kernel, driver, or firmware. The finding remains
experimental and open.
